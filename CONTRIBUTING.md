# Contributing

Start with docs/BUILDING.md and the public component checks. Keep changes small, explain behavior and add tests for security/protocol changes. Distinguish host tests, mocked peers and real guest observations.

Do not commit keys, tokens, VM disks, personal/classroom files or Windows remote-control configuration. Preserve upstream notices. Do not weaken sandbox policies to make tests pass.

Use descriptive commits for actual changes. Empty commits, backdated history and artificial activity are not part of this project's workflow.
